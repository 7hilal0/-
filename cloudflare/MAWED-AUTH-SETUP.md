# إعداد ربط تسجيل الدخول في موعد مع بوت محمود

## الملفات
- `mawed-auth-worker.js`: API لإرسال كود مؤقت من 4 أرقام على الخاص والتحقق منه.
- `mawed-auth-schema.sql`: جداول D1 لحفظ تجزئة الكود ومحدودية المحاولات.
- واجهة الموقع تستدعي:
  - `POST /auth/request` مع `{"username":"DiscordUsername"}`
  - `POST /auth/verify` مع `{"username":"DiscordUsername","code":"1234"}`

## قبل التفعيل الإنتاجي
هذا الملف Worker مستقل؛ لم يُنشر بعد ولم تُضف أسراره/روابطه إلى Cloudflare. كما أن نجاح التحقق حاليًا لا ينشئ جلسة موقع دائمة. لا تعتبر المستخدم مسجل دخول فعليًا حتى تُضاف جلسة موقعة (Cookie آمنة أو JWT) وتُربط بحماية الصفحات/API.

1. أنشئ D1 database جديدة لموعد ولا تستخدم قاعدة dzcore الإنتاجية.
2. نفذ `mawed-auth-schema.sql` على قاعدة D1 الجديدة.
3. أنشئ Worker جديد باسم مثل `mawed-auth`، والصق `mawed-auth-worker.js`.
4. اربط D1 باسم `AUTH_DB`.
5. أضف Secrets: `DISCORD_BOT_TOKEN`, `CODE_PEPPER`, `RATE_LIMIT_SALT`.
6. أضف متغيرات غير سرية: `DISCORD_GUILD_ID` بمعرّف سيرفر محمود، و`ALLOWED_ORIGIN` بالأصل الكامل الصحيح للموقع (مثلاً `https://7hilal0.github.io`، تأكد من عنوان موقعك النهائي).
7. تأكد أن البوت عضو في السيرفر ويستطيع البحث عن الأعضاء. لأن API لا يمكنه إرسال رسالة خاصة اعتمادًا على اسم المستخدم وحده إلا بعد حل الاسم إلى حساب حقيقي؛ إذا لم يظهر العضو عبر بحث السيرفر، لا يوجد إرسال.
8. بعد النشر، حدّث نقطتي النهاية في `index.html` إلى رابط Worker الحقيقي.
9. نفذ اختبارًا بحسابك أولًا ثم جرّب انتهاء الكود وتكراره والحد من التخمين.

## تنبيه أمني عاجل
أثناء الفحص، ظهرت قيم حساسة في إعدادات Worker الحالي `discord` بوصفها `plain_text`، مثل رمز البوت ومفتاح Gemini وسر التسجيل. ينبغي تدوير/إعادة إصدار هذه المفاتيح ونقلها إلى Secrets في Cloudflare؛ لا تعاود نشرها أو مشاركتها. لم أغيّر Worker محمود الحالي حتى لا أكسر وظائفه.

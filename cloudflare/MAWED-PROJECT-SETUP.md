# إعداد مشروع موعد (Maw'ed) الكامل

الموقع والبوت وخدمة الربط موضوعة في **مستودع GitHub واحد**: `7hilal0/-`.

## المكونات
- `index.html`: واجهة الموقع المنشورة على GitHub Pages.
- `cloudflare/mawed-auth-worker.js`: API لطلب رمز Discord والتحقق منه.
- `cloudflare/mawed-auth-schema.sql`: مخطط قاعدة D1 الخاصة بموعد.
- تطبيق Discord باسم Maw'ed: هوية البوت الذي يرسل رموز التحقق.

> وجود الملفات في مستودع واحد لا يعني أن الخدمة منشورة تلقائيًا. GitHub Pages يستضيف الواجهة فقط؛ Worker وقاعدة D1 يجب إعدادهما على Cloudflare.

## إعداد Cloudflare
1. أنشئ قاعدة D1 جديدة باسم `mawed-auth-db`؛ لا تستخدم قاعدة بيانات أي مشروع آخر.
2. افتح قاعدة البيانات ونفّذ محتويات `mawed-auth-schema.sql`.
3. أنشئ Worker باسم `mawed-auth` وانسخ إليه `mawed-auth-worker.js`.
4. اربط قاعدة D1 بالـ Worker باسم `AUTH_DB`.
5. أضف Secrets في إعدادات Worker:
   - `DISCORD_BOT_TOKEN`: Bot Token لتطبيق Maw'ed فقط.
   - `CODE_PEPPER`: قيمة عشوائية طويلة.
   - `RATE_LIMIT_SALT`: قيمة عشوائية طويلة أخرى.
6. أضف متغيرات نصية:
   - `DISCORD_GUILD_ID`: معرّف سيرفر Discord الذي انضم إليه بوت Maw'ed.
   - `ALLOWED_ORIGIN`: `https://7hilal0.github.io` (الأصل، بدون مسار المستودع).
7. تأكد أن البوت موجود في السيرفر، وأن الأعضاء يسمحون بالرسائل الخاصة.
8. بعد نشر Worker، حدّث عنوان API في الواجهة إلى رابط Worker الحقيقي واختبر طلب الرمز والتحقق.

## حالة تسجيل الدخول
واجهة التحقق الحالية تجريبية إلى أن يُنشر الـ Worker وتُحدّث عناوين API. وحتى بعد نجاح التحقق، لا تعتبر الحساب مسجّل دخول دائمًا قبل تنفيذ جلسة آمنة موقعة (Cookie آمنة أو JWT) والتحقق منها في الخادم.

## الأمان
- لا تضع Bot Token أو أي سر في `index.html` أو GitHub.
- لا ترسل Bot Token في المحادثة.
- لا تستخدم قاعدة بيانات موجودة لمشروع آخر.
- لا تُعلن أن الربط اكتمل قبل اختبار الإرسال والتحقق فعليًا.
